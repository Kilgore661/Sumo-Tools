# Findings: P1-WL website build and inspection

## Decision

The P1-WL website built successfully, was served from the shared workspace
preview, and showed no obvious problems during user inspection. This completes
the Kimarite matter.

The inspection was deliberately pragmatic rather than exhaustive. Together
with the preceding prior evaluation and controlled site-bundle comparison, it
is sufficient evidence that including represented W/L results without
kimarite does not introduce a material downstream problem.

## Ownership and production isolation

The Kimarite entry point owned input verification, provenance and output. It
used the unchanged `make_site89` assembler as a dependency. The generated site
was written entirely beneath this work package.

The build manifest records `deployment_invoked: false`. Nothing was copied to
`A:`, the ordinary `make_site89` output was not overwritten, and the canonical
P1 prior was not replaced.

## Shared inspection

The generated `site/` tree was served successfully at:

```text
http://localhost:8766/
```

The user loaded the working website and reported no obvious problem. This
confirms that the retained candidate can cross the static assembly and HTTP
serving boundary and function as a website visible to both participants.

No claim is made that every page state, viewport, interaction or value was
exhaustively checked. In particular, the deferred principled comparison of
chii was not reopened because the downstream website exposed no concrete
problem requiring it.

## Final Kimarite conclusion

A represented binary W/L result remains rating evidence when its kimarite is
missing. P1-WL applies that rule consistently. Its fitted prior is acceptable,
its downstream rating changes are controlled, model-independent site outputs
remain unchanged, sekitori competitive differences are small, and the
assembled site presents no obvious regression.

The Kimarite investigation is therefore closed. Installing P1-WL as the
canonical production prior, regenerating ordinary production outputs and
deploying them are operational changes outside this completed validation
matter and still require explicit action.
