# 04.5.3 Basho Results Model - Public Projections and Analysis

Refactored from $source.

## 6. Public Projection Options

The current Basho Results projection is deliberately simple and ad hoc. It is
not a general theory of hierarchical table options.

```text
Previous Basho
  shows the `before` record.

Changes
  shows the `changes` group. This option is default-on.
  When visible, Changes presents `changes.delta_equelo` before
  `changes.movement` where both are projected.

Equelo Ratings
  shows `*.context.skill.equelo`.
  When Changes is also selected, it additionally shows `changes.delta_equelo`.
  It does not show Ratings Fit merely because Ratings Fit depends on ratings.

Ratings Fit
  shows `*.context.analysis.*` as one monolithic subtree: BZ Error direction,
  BZ Error magnitude and RBBP.

nuChii
  shows `selected.next_bp`.
```

The minimal default selected projection is:

```text
selected.context.skill.bp
selected.result.wins
selected.result.losses
selected.result.absences
selected.result.prizes
changes.movement.bp
changes.movement.division
```

If the `Changes` option is off, the minimal selected projection excludes the
`changes` group.

When a projected group has only one visible child, the current renderer may still
show the intermediate group headings. That is acceptable for now and does not
trigger a general hierarchical table projection/collapse theory.

## 7. Result Decomposition

Basho Results does not treat a compact result string as the final public model.
A result is logically decomposed into:

```text
wins
losses
absences
prizes
```

`prizes` remains a compact displayed value. For ordering, prizes are interpreted
as an ordered six-bit value over the current compact display basis:

```text
Y D J K S G
```

The basis is listed from most valuable to least valuable. The least valuable
prize, `G`, is bit 0. A prize bit is 1 iff that prize was awarded. Descending
prize order therefore means better prize sets first; a prize set containing `Y`
sorts above any prize set without `Y`, and blank/no-prize values sort last.

Other result fields are logically separate even if a later view chooses to
display them compactly.

The current renderer still contains transitional parsing where producer output
has not yet emitted the final decomposed shape. That parsing is a migration seam,
not the final model. Until the structured Result emitter shape issue is fixed,
the runtime derives the prize sort value from the compact prize display text.

## 8. Rating-Order Analysis Model

Basho Results may compare official BP order with Equelo order for the same
selected table population.

For a given record:

```text
banzuke_position
  position when rows are ordered by official BP/Chii;

rating_position
  position when rows are ordered by Equelo rating;

signed_bz_delta
  banzuke_position - rating_position;

rbbp
  the official BP slot at rating_position in the BP-ordered slot list.
```

`signed_bz_delta` is an implementation convenience, not the public model. The
public BZ Error / DeltaBZ value is decomposed into:

```text
direction
  up      rating_position is higher than banzuke_position;
  down    rating_position is lower than banzuke_position;
  none    positions are equal or the comparison cannot be made;

magnitude
  absolute distance between banzuke_position and rating_position.
```

An upward direction means the rating order places the rikishi higher than the
official banzuke order. A downward direction means the rating order places the
rikishi lower than the official banzuke order.

RBBP is the rating-based BP slot, not a prediction of actual promotion or
placement by the banzuke committee. It ignores promotion rules, rank-holding
conventions, vacancies and other banzuke-making constraints. It answers only:

```text
If the selected population occupied the same BP slots in Equelo order, which BP
slot would this rikishi occupy?
```

The output paths are:

```text
before.context.analysis.banzuke_error.direction
before.context.analysis.banzuke_error.magnitude
before.context.analysis.rbbp
selected.context.analysis.banzuke_error.direction
selected.context.analysis.banzuke_error.magnitude
selected.context.analysis.rbbp
```

These paths belong to `context.analysis` because they are derived analysis about
the represented record's context, not raw skill indicators and not results.

## 9. Temporal Resolution

For the `before` record:

```text
before.context.skill.bp
  predecessor-basho BP

before.result.*
  predecessor-basho result values

before.context.skill.equelo
  pre-selected-basho Equelo rating

before.context.analysis
  predecessor-basho banzuke slots plus pre-selected-basho rating order
```

For an in-progress selected basho:

```text
selected.context.skill.bp
  selected-basho BP

selected.result.*
  selected-basho results through the represented day

selected.context.skill.equelo
  day-end Equelo rating after the represented day

selected.context.analysis
  selected-basho banzuke slots plus day-end rating order
```

For a completed selected basho:

```text
selected.context.skill.bp
  selected-basho BP

selected.result.*
  final selected-basho result values

selected.context.skill.equelo
  post-basho/final-day Equelo rating

selected.context.analysis
  selected-basho banzuke slots plus post-basho rating order
```

`selected.next_bp` is successor BP context and is shown by the current
transitional `nuChii` option. `changes.movement.bp` and
`changes.movement.division` compare selected BP context with successor BP context
where known.

Operational data availability may lag the ideal date/time-derived state. That is
an operations/build-data concern, not a change to the pure table model.
