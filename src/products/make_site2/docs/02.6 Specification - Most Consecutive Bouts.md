# 02.6 Specification - Most Consecutive Bouts

## Status

Settled first-pass specification for Sumo History > Records > Most consecutive
bouts.

This page is a promoted Records page. It is intentionally about named rikishi
and belongs under Sumo History rather than Rikishi because the public question
is historical record comparison across individuals.

---

## 1. Public Question

The page answers:

```text
Which rikishi have the longest consecutive-bout appearance streaks?
```

The public unit being ranked is a rikishi's longest observed streak of
consecutive confirmed appearances in History.

---

## 2. Consecutive-Bout Definition

For this page, consecutive bouts means consecutive daily appearances as
represented by History, with streaks broken by absences.

The producer shall derive streaks from daily History evidence rather than from
torikumi alone. A scheduled bout and an actual appearance are not equivalent for
this purpose.

Daily evidence is interpreted as follows:

- a confirmed bout appearance extends the current streak;
- an explicit no-show breaks the current streak;
- a sekitori missing a represented day breaks the current streak;
- a non-sekitori basho with unresolved no-bout days survives only if the
  rikishi has the expected number of confirmed appearances for that basho; and
- a known sanctioned absence may be declared not to break the streak.

The current sanctioned-absence list contains Tamawashi's 2022/07 Covid-era
heya-quarantine withdrawal. This absence does not count as a bout, but it also
does not break the streak.

---

## 3. Public Artifact

The PA is an ordinary flat table headed:

```text
Most Consecutive Bouts
```

The table columns are:

| Column | Meaning | Sortable |
| --- | --- | --- |
| blank | row number after current filtering and sorting | no |
| `#` | record position in the default longest-streak ordering | yes |
| `Shikona` | rikishi shikona, linking to SumoDB | yes |
| `Bouts` | confirmed appearances in the longest streak | yes |
| `Start` | first appearance in the streak | yes |
| `End` | final appearance in the streak, or `-` for an open streak | yes |
| `Clean` | whether the rikishi has never missed a day in his entire career | no |

`Start` and `End` values use `YYYY/MM/DD`, where `DD` is the basho day number,
not a civil calendar day. Their popover text is:

```text
year/month/day of basho
```

`Clean` renders as a tick when true and blank when false. Its popover text is:

```text
See Notes
```

The `Clean` Note says:

```text
A "clean" record is one where the rikishi has never missed a day in his entire career.
```

---

## 4. Filters and Public State

The page has one option:

```text
Clean only?
```

It is a checkbox, unchecked by default. The canonical default public view link
therefore includes:

```text
clean_only=false
```

When `Clean only?` is unchecked, the table shows the published longest-streak
candidates. When checked, it shows only rows whose `Clean` value is true. The
row-number column is recomputed after filtering and sorting; the `#` column
continues to show the rikishi's position in the default longest-streak ranking.

---

## 5. Data Contract

The staged CSV for the PA is:

```text
sumo-history/records/most-consecutive-bouts/data/longest_streak_candidates.csv
```

The source CSV is currently produced at:

```text
files/output/analysis/sumo_history/records/consecutive_bouts/longest_streak_candidates.csv
```

Required fields are:

```text
position,rikishi_id,shikona,bouts,clean,start,end
```

`rikishi_id` is required even though it is not a visible table column, because
the public `Shikona` values link to SumoDB.

---

## 6. Open Design Context

This page deliberately exposes both a row-number column and a ranked-position
column. The row-number heading is blank and the ranked-position heading is `#`.

The broader row-number/rank-heading policy is still open and is tracked in
`10.4 Open Issues - Defects and Deferred Matters.md` under Table Row Number
Policy.
