# 04.5.4 Basho Results Model - Temporal Alignment and Sorting

Refactored from $source.

## 10. Movement and Change Terms

Three arrow-like concepts are distinct and shall not be collapsed:

```text
BP movement
  Whether selected BP context moved up/down relative to successor BP context.
  This is a Basho Results Changes value.

Divisional movement
  Whether selected broad rank/division context moved up/down relative to
  successor broad rank/division context. For this purpose Y, O, S and K are
  treated as distinct rank-level divisions. This is a Basho Results Changes
  value.

Banzuke Changes movement
  Whether a rikishi actually moved up/down in the official banzuke from one
  basho to the next. This is the 2.1 Banzuke Changes movement feature.

BZ Error / DeltaBZ
  Whether rating order places the rikishi above/below their official BP order,
  plus the absolute size of that discrepancy. This is Basho Results Analysis.
```

Basho Results renders Delta Equelo followed by BP movement and Divisional
movement under `changes` when the Changes option is selected and the relevant
rating/movement values are projected. Banzuke Changes renders its own Movement
feature. Basho Results renders BZ Error / DeltaBZ and RBBP under
`context.analysis` when the Analysis option is selected.

## 11. Presentation Alignment

Basho Results has a 7.1-local table-cell alignment policy. It is deliberately
smaller than a general table-presentation theory and does not decide how
ordinary/non-7.1 tables should align their headings or values.

For Basho Results, horizontal alignment is determined by two properties of the
rendered cell:

```text
role
  heading
  value

semantic presentation kind
  default
  name
  rank_code
  rating
  compact_count
  movement_symbol
  numeric_magnitude
  compact_text
```

The current 7.1 mapping is:

```text
heading + name
  left

heading + any other kind
  centred

value + name
  left

value + rating
value + numeric_magnitude
  right

value + rank_code
value + compact_count
value + movement_symbol
value + compact_text
value + default
  centred
```

This means, for example:

```text
reference.shikona
  heading left, values left

reference.row_number
  heading centred, values right

*.context.skill.bp
selected.next_bp
*.context.analysis.rbbp
  heading centred, values centred

*.context.skill.equelo
changes.delta_equelo
*.context.analysis.banzuke_error.magnitude
  heading centred, values right

*.result.wins / losses / absences
changes.movement.*
  heading centred, values centred
```

The policy applies to rendered headings as headings. It does not distinguish
column-group headings from terminal headings for alignment, and it does not
introduce heading-collapse or projection-collapse semantics. Those questions
belong to a later table-projection theory if real pressure appears.

Sortable 7.1 headings reserve enough horizontal space for the heading text plus a
sort indicator. When a column is not the active sort, the heading text is centred
inside that reserved width. When a column is the active sort, the heading text
plus indicator is centred inside the same reserved width. This keeps headings
visually centred while preventing column-width churn when the sort indicator is
shown or hidden.

## 12. Sorting

Basho Results follows the ordinary table sorting contract, adapted to recursive
terminal paths.

```text
Ordinary flat table:
  sortable column identity = flat column id

Basho Results recursive table:
  sortable column identity = recursive terminal path
```

A sortable Basho Results column is a visible leaf heading: a terminal heading
that sits above exactly one data column.

Rules:

- every visible leaf heading is sortable by default;
- `reference.row_number` is a reference column and is not sortable;
- group headings are not sortable because they do not identify one data column;
- clicking a sortable leaf heading sorts rows by that leaf column's sort value;
- clicking the active sorted leaf heading reverses the sort direction;
- the active sorted leaf heading visibly indicates direction and exposes
  equivalent accessible state;
- row numbers are renumbered after filtering and sorting.

The default Basho Results sort is `selected.context.skill.bp` descending in
public Chii/rank-order terms: top ranks first. Internally, Chii/BP columns sort by
emitted ordinal values where lower ordinals represent higher ranks, so public
rank-order descending is implemented as ordinal ascending. Clicking the active
Chii heading reverses to lower-rank-first order.

Prizes sort by the ordered six-bit prize value described in Result Decomposition,
not by display text. The first click on a Prizes heading sorts descending, shows
the down-arrow state, puts the best prize sets first, and puts blank/no-prize
values last. Clicking the active Prizes heading reverses to ascending order, with
blank/no-prize values first and the best prize sets last.
