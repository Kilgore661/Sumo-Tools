## 5. New Defect: Empty Plotly Line Charts

**Status:** Open; reproduce, scope and diagnose.

Pages rendering Plotly line charts have been observed to display a chart frame
without visible traces. The affected Pages, states and cause have not yet been
established.

Investigation shall determine whether data files load and contain rows, whether
runtime errors occur, whether traces are constructed before Plotly invocation,
and whether the problem affects only line charts or other Plotly renderers.
A reliably empty promoted chart PA is a material rendering failure.

This defect does not reopen the canonical-link correction.

| Equelo API tidy before further chart work | Open / Next | Do the bounded Equelo tidy before continuing Career Comparisons chart implementation. Story: Equelo ratings are defined on the observable SumoDB bout domain, not on every raw banzuke chii. Before 1989, SumoDB does not contain full lower-division bout data; the Oracle keeps bouts involving at least one sekitori, retains all raw-banzuke sekitori in the rating universe, and adds lower-division participants only when they appear in retained bouts. A lower-division rikishi/chii can therefore exist in raw History but never enter the Equelo observable network. Such a rikishi cannot have an Elo-like rating, and a chii that never appears in retained bout data cannot get a fixed-point entrant rating. The earlier assumption that every chii eventually gets a rating because it appears on a banzuke was wrong. The correct API type is `float | None`, and every rating consumer must handle `None` deliberately. Current no-rating chii are documented by `src.analysis.equelo.validate`, which writes `files/output/equelo/obscure_chii.csv`; the current domain is `Ms61e` through `Ms101w` and `Sd101w` through `Sd120e`. Work plan: (1) keep `src.analysis.equelo.api` as the documented additive API surface for fixed_v2 rating lookup, including `EqueloTiming`, `EqueloLookup`, `get_equelo(...) -> float | None`, and `no_rating(...)`; (2) maintain this Story of Nones in `src/analysis/equelo/README.md`; (3) keep `src.analysis.equelo.validate` as the validation/report module, with `obscure_chii.csv` documenting raw-History chii outside the fixed_v2 rating domain and cross-checking `no_rating(...)`; (4) remove proof-of-concept debris such as any clipping/nearest-rank policy text or stale non-optional API claims; (5) add focused API tests for normal before/after lookup, annotated-chii entrant lookup, `None` lookup for a no-rating chii, and validation/report consistency; (6) continue migrating non-BRB consumers only after their semantics are reviewed. |
