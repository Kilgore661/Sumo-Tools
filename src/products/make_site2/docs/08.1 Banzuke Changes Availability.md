# 08.1 Banzuke Changes Availability

## Status

Focused design refinement for Page 2.1. This document governs where earlier general Selected-History wording in `04.2`, `07` or `08` implies that Banzuke Changes is an ordinary comparison of the final two bashos in an arbitrary selected History.

## Production Semantics

Banzuke Changes is a **new-banzuke change report**. It answers: a newly published banzuke is available before its basho has results of its own; how does it differ from the preceding represented basho?

Its production inputs are:

```text
predecessor context
  the latest relevant BashoState in History;

successor subject
  a compatible separately available newly published banzuke which has not yet entered History with results of its own.
```

It is not a general adjacent-historical-basho comparison Page. Basho Results serves represented historical bashos and their predecessor comparison.

## Availability

In production, 2.1 is available only where the required compatible successor banzuke exists relative to the site's History. Otherwise its Navigation entry shall not invite ordinary selection and a direct request shall explain:

```text
No newly published banzuke is currently available.
Use Basho Results to compare a represented basho with its predecessor.
```

## Temporary Development Exception

Developers must be able to regress 2.1 outside its short production availability window. A development build may therefore keep the Page selectable and display its existing prepared/live report without establishing production availability.

That exception is not production semantics. It must be conspicuous in the visible subheading after `New-banzuke change report.`, materially equivalent to:

```text
DEVELOPMENT WARNING: availability is not yet validated against this build's History. This Page is intended only for a newly published banzuke before its first results enter History; archive or historical builds may show unrelated live output.
```

The default non-`--prod` build is the intended development mode. `--prod` is the intended production mode; when availability enforcement is implemented it shall render the normal Page only when available, and otherwise render unavailable treatment. Until then, production-intent output must not silently conceal the warning while still exposing unvalidated Banzuke Changes material.

## Immediate Implementation Step

Leave the existing Banzuke Changes data/report path unchanged. Add the visible development warning using build-mode presentation context. Production availability enforcement and disabled/unavailable Navigation treatment are later implementation work.
