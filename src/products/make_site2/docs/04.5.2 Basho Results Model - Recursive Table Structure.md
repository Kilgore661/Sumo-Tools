# 04.5.2 Basho Results Model - Recursive Table Structure

Refactored from $source.

## 3. Recursive Table Specification

A Basho Results table specification is an ordered recursive keyed structure:

```text
TableSpec ::= S+
S ::= <key> : (<terminal column> | TableSpec)
```

The maximal Basho Results frame is:

```text
BashoResultsFrame ::=
[
  reference: ReferenceSpec,
  before: RecordSpec,
  selected: RecordSpec,
  changes: ChangesSpec
]
```

The maximal known structure is:

```text
reference
  row_number
  shikona

before
  context
    skill
      bp
      equelo
    analysis
      banzuke_error
        direction
        magnitude
      rbbp
  result
    wins
    losses
    absences
    prizes

selected
  context
    skill
      bp
      equelo
    analysis
      banzuke_error
        direction
        magnitude
      rbbp
  result
    wins
    losses
    absences
    prizes
  next_bp

changes
  delta_equelo
  movement
    bp
    division
```

The current implementation covers this transitional slice of the model:
reference columns, before/selected BP, decomposed result columns, Equelo context,
monolithic Analysis projection containing BZ Error / DeltaBZ and RBBP, `nuChii`
where available, `delta_equelo`, and movement BP/Div changes. Producer output is
still transitional in places, especially compact result strings and client-side
derivation of Analysis and movement values.

## 4. Records, Context, Skill, Analysis and Result

A Basho Results **record** is the before-basho or selected-basho row object for a
rikishi. In the presentation model:

```text
before :: record
selected :: record
```

A record has two main parts:

```text
record
  context
  result
```

`context` contains non-result information about the rikishi at that represented
basho point:

```text
context
  skill
    bp
    equelo
  analysis
    banzuke_error
      direction
      magnitude
    rbbp
```

`skill.bp` is the official BP/Chii slot. `skill.equelo` is the rating value for
the represented point. `analysis` contains values derived from comparing the BP
ordering and the Equelo ordering. Analysis is intentionally monolithic for the
current UI: the public `Analysis` option controls the whole analysis subtree. A
future design may split it only if real pressure appears.

`result` contains the decomposed score information for that record:

```text
result
  wins
  losses
  absences
  prizes
```

Movement/change values are not result fields in this model. They compare the
selected record with successor BP context where known, so they belong to the
top-level `changes` group.

## 5. Terminal Paths and Values

Terminal paths are the stable column identities in the Basho Results recursive
table. They play the role that flat column ids play in ordinary table PAs.

Examples:

```text
reference.row_number
reference.shikona
before.context.skill.bp
before.context.skill.equelo
before.context.analysis.banzuke_error.direction
before.context.analysis.banzuke_error.magnitude
before.context.analysis.rbbp
before.result.wins
before.result.losses
before.result.absences
before.result.prizes
selected.context.skill.bp
selected.context.skill.equelo
selected.context.analysis.banzuke_error.direction
selected.context.analysis.banzuke_error.magnitude
selected.context.analysis.rbbp
selected.result.wins
selected.result.losses
selected.result.absences
selected.result.prizes
selected.next_bp
changes.delta_equelo
changes.movement.bp
changes.movement.division
```

Terminal paths resolve to concrete display values or null/empty values. Public
options project or hide parts of the resolved table; options do not decide
whether values conceptually exist.

Reader-facing labels may be shorter than stable model path names. Current labels
include `Chii` for `bp`, `Eq` for `equelo`, `ΔEq` for `delta_equelo`, `ΔBZ` for
`banzuke_error`, and `Eq Chii` for `rbbp`.

A terminal path may have a separate sort-value path where the displayed value is
not the correct sortable value. Chii/BP display values shall sort by emitted
ordinal values, not by runtime parsing of display strings. The public sort
direction for Chii/rank-code columns is rank-order direction rather than raw
ordinal direction: descending means top ranks first, even though top ranks have
the lowest underlying ordinal values.
