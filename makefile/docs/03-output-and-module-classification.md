# Output and Module Classification

## Legacy and Non-Legacy

An output, producer or consumer is **legacy** if it is no longer part of any current or intended line of work.

An output, producer or consumer is **non-legacy** if it is current, intentionally retained, required by a named future use, valuable as a selected research record, or attached to an active diagnostic workflow.

"Potentially useful someday" is not enough.

## Output Layers

### Source Capture

Raw or near-raw material captured from outside the project.

Examples:

```text
downloaded SumoDB HTML
raw source snapshots
manual source files used as data
```

### Canonical Data

Coherent internal project data that other tools are allowed to rely on.

Examples:

```text
History zip
LiveStore History-equivalent data
parsed rikishi bio JSON, if promoted
```

### Producer Output

Analysis-specific, product-specific or tool-specific output produced from source capture, canonical data or other producer outputs.

Examples:

```text
analysis CSV
site-facing input
process cache
diagnostic report
research chart
standalone browser app
```

### Publication Output

A generated static publication tree or deployable output.

Examples:

```text
make_site2 output tree
copied route data
runtime files included in a static site build
```

### Runtime View

A browser-realised view created from static files and URL/filter/runtime state.

Runtime views are not usually files. Include them only when a browser runtime consumes generated files to create material user-visible state.


## Module Classifications

Use these labels:

```text
active producer
legacy producer
support module
research module
redundant module
entry point only
unknown
```

### active producer

Produces at least one non-legacy generated output.

### legacy producer

Produces generated outputs, but all known outputs are legacy.

### support module

Imported by non-legacy code, even if it produces no current outputs itself.

### research module

Retained because it encodes an active or selected research method.

### redundant module

Produces no non-legacy output, supports no non-legacy code, has no retained research value and is not protected by tests/docs as an active object.

### entry point only

The command-line or script entry point is obsolete, but reusable logic inside the module may be retained or refactored.

## Deletion Policy

Generated files do not earn a permanent place merely by existing.

Keep a generated output live only if it is:

```text
canonical
used by a non-legacy consumer
an unused non-legacy leaf
a declared future input
a selected research record
an active diagnostic
```

Delete or quarantine a generated output if it is:

```text
unused legacy
used only by legacy consumers
unproven as current but easy to regenerate
duplicate
stale debug material
generated by a redundant module
```

Delete a module only if it is redundant. If a module contains reusable logic but its output-producing entry point is legacy, prefer deleting or disabling the entry point first.
